# Chunk 7 — Reviewer A (Correctness & data integrity) — submodule interfaces + dead infra

## Findings

### A-7-01: `crossproduct.py`'s hardcoded output path points at the stale `crossproduct/` directory, not the corrected `crossproduct_v2/` directory the current authoritative docs cite

- **File:line (test-bed side)**: `test-bed/src/Modules/robust_testing/kradar/scripts/analysis/crossproduct/crossproduct.py:32` — `SUMMARY_OUT_DIR = AMSCUP_ROOT / "repos" / "K-Radar" / "outputs" / "robustness_reports" / "crossproduct"`. This constant is imported and reused as the single source of truth for all read/write paths in `run_analysis.py:41,52,74` and `queries.py:28,43,47,315` (`REPORT_DIR = SUMMARY_OUT_DIR / "reports"`, `pl.read_parquet(SUMMARY_OUT_DIR / f"summary_{level}.parquet")`, etc.). `plots.py:26` independently hardcodes the same stale `.../crossproduct/figures` path.
- **Path on submodule side**: `repos/K-Radar/outputs/robustness_reports/` currently contains BOTH `crossproduct/` (last written Aug 31 23:11, e.g. `findings.md` at 23:11 with 4854 bytes) and `crossproduct_v2/` (last written Sep 2 20:13, `findings.md` at Sep 1 11:22 with 4794 bytes, described in its own directory name as a v2/corrected rebuild). `docs/crossproduct_trends_and_anomalies.md:7,16` states explicitly: "Fully re-derived 2026-09-01 against `crossproduct_v2/`" and "Every number below was re-pulled directly from `crossproduct_v2/`, not [the old crossproduct/ build]" — i.e. the project's own current documentation treats `crossproduct_v2/` as the authoritative, current build, and `crossproduct/` as the superseded one.
- **Failure scenario**: `SUMMARY_OUT_DIR` was never updated to point at `crossproduct_v2` — it still says `"crossproduct"`. If anyone reruns `uv run python scripts/analysis/crossproduct/run_analysis.py` (or any script importing `SUMMARY_OUT_DIR`) today, expecting it to refresh the currently-cited `crossproduct_v2/` build, it will instead silently read/write the old `crossproduct/` directory — regenerating stale-methodology output under the old path while leaving `crossproduct_v2/` (the path every current doc cites) completely untouched and increasingly out of sync with the actual code. Anyone downstream trusting `crossproduct_v2/` as "current" after such a rerun would be looking at data from before whatever fix motivated the rerun. This is the inverse of a doc-drift problem — the code's own path constant is what's stale, and it points at a real, on-disk directory that looks legitimate (it has all the expected files), so nothing errors or warns.
- **Severity**: silent wrong output — no exception, no missing-file error; the script runs successfully and produces output that looks complete but lands in the wrong directory relative to what the rest of the project currently treats as canonical.
