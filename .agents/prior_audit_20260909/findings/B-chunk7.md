### B-7-01: `description.txt` files that `weather`/`environment`/`time_of_day` columns depend on don't exist in the local K-Radar checkout — architecture.md's schema description is now permanently unrealizable, not just occasionally missing

- **Doc**: `test-bed/src/Modules/robust_testing/kradar/architecture.md:251-253` — Output Schema table: `weather | str | description.txt field 3 (validated against ALLOWED_WEATHER, fallback "normal")`, `environment | str | null | description.txt field 1 ('location' key), unvalidated`, `time_of_day | str | null | description.txt field 2 ('time' key), unvalidated`. Also `:86` — `parse_description_txt(sequence_id, dataset_root) -> dict (keys: location, time, weather)`, presented as a normal data-sourcing function.
- **Reality**: `find /home/adhish/Productivity/AMSCUP/repos/K-Radar -iname "description.txt"` returns zero results — no `description.txt` file exists anywhere in the local `repos/K-Radar` submodule checkout. `parser.py:142-153` (`parse_description_txt`) does `desc_path = dataset_root / "data" / sequence_id / "description.txt"; if not desc_path.exists(): return {}` — every call against the local dataset returns `{}`, so every row's `weather` gets the "normal" fallback, and `environment`/`time_of_day` get `null`, for every sequence, unconditionally. `obsidianVault/Daily/2026-09-07.md:20-22` independently confirms this is a known, permanent condition: "a weather-per-sequence join defaulting to 'normal' for every sequence because the raw dataset's `description.txt` files don't exist in this local checkout (only ever lived on Alvis)."
- **Contradiction**: architecture.md's schema table describes `weather`/`environment`/`time_of_day` as if they are populated from real per-sequence metadata (with only `weather` having a documented fallback path, and even that framed as an edge case, not the permanent, universal case it actually is locally). Since Alvis is confirmed permanently gone (2026-09-01, ground truth) and the daily note states these files "only ever lived on Alvis," this isn't a transient gap — it's now a structural, permanent limitation: **no local kradar_visibility run can ever produce a real weather/environment/time_of_day value**, only the universal fallback/null. This also directly explains chunk 2's B-2-flagged VER-25/VER-26 (`TestWeatherImpact`) being unconditionally `pytest.skip`ped — those tests cannot run against real weather data because the data doesn't exist locally and never will again.
- **Severity**: doc-drift (the schema description is not literally false — `parse_description_txt` really does read those keys when the file exists — but it presents a now-permanently-unreachable code path as the normal/primary behavior, which will mislead anyone using architecture.md to interpret current or future output. Not scored as "silent wrong output" because the code's fallback behavior is intentional and documented as *a* fallback — the drift is that the doc doesn't communicate the fallback is now the *only* reachable path.)
