## Phase 1 mechanistic audit of the LiDAR-Gaussian-noise mAP collapse

Read-only audit (no training/config/hook changes, no forward pass). Stage A
(parquet-only failure-mode breakdown, `row_table_iou03.parquet`): confirmed the
AP collapse under `lidar_gaussian_noise_{medium,high}` is FN-driven, not
localization- or FP-driven — FN rate sed 22%→85%→86%, bus 29%→70%→75%; FP rate
flat/dropping; mATE on survivors up only ~40-45%. Stage B (code read):
independently re-derived the same root cause already in
[[asf-availability-told-not-aware]] (`a2_fusion.py`'s only gate is a hardcoded
presence/absence string, never touched by Gaussian-noise conditions, no
learned quality signal anywhere) — good cross-check, added as an addendum
there rather than a new note. Stage C: confirmed (again) raw point clouds
aren't local, `repos/K-Radar/data` is a dead-on-traversal sshfs mount to
Alvis.

New finding worth surfacing: `repos/K-Radar/pretrained/` (holding
`ASF_v2_0_final_10.pt`, the checkpoint the task brief called "local") is *also*
an sshfs mount to Alvis, and — unlike `data` — it actually served a real read
during this session (`dd`'d 20MB in ~1.6s). Flagged as a blocking question
rather than silently resolved either way: doesn't fully square with
[[project_alvis_permanently_unavailable]] for passive file access, and any
Phase 2 forward-pass work should copy the checkpoint to true local disk rather
than depend on the mount staying up. Full report, all four stages, and 4
explicit blocking questions in
`docs/vAIlt/06_Results/lidar-gaussian-noise-mechanism-phase1-audit-20260902.md`.
