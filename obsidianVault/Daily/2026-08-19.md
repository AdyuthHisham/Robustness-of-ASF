# 2026-08-19

## Metrics literature audit for ASF corruption-robustness evaluation

Read all 10 papers in `docs/lit_survey/metrics/` (Hendrycks & Dietterich,
Kamann & Rother, Philion et al.'s PKL, Dong et al., Gao et al., RoboBEV,
MSC-Bench, RobuRCDet, RoHOI, S2R-Bench) via parallel extraction agents, then
synthesized `docs/lit_survey/metrics/metrics_audit.md` — per-paper metric
tables, a recommended metric stack, an exclusion table, and source-conflict
notes.

Key finding: RoboBEV's own headline metric (mCE) needs a second baseline
model — "RoboBEV-style retention percentage" should mean RoboBEV's secondary
metric (RR/mRR), which is self-relative. That formula turns out to be
independently reinvented across four papers under different names (RS/mRS,
RCE, Rb/mRb) — AMSCUP's own `compute_robustness.py` already implements it as
`Rb^c`/`mRb`. Full writeup in [[robustness-metric-selection]].

Resolved four open blocking questions from the audit by analyzing the
existing Alvis inference tooling rather than designing from scratch:
1. **Base task metric** — already fixed by the existing pipeline: KITTI-style
   AP, per-class, BEV+3D, IoU {0.7,0.5,0.3} — confirmed by reading
   `compute_robustness.py`'s `complete_results.txt` parser. RR/mRR and CRI
   should be an aggregation layer on top of this, not a new metric.
2. **mAVE** — confirmed excluded; K-Radar's label schema has no velocity data.
3. **CRI's severity-count sensitivity** — explained in depth (n=3 vs. RoHOI's
   validated n=5; degrees-of-freedom and nonlinearity-detection arguments).
   Resolution: report CRI as secondary to RR/mRR with the caveat disclosed.
4. **frame_deletion vs. loss_complete diagnostic** — scope reduced per
   direction to a feasibility check on existing sweep data rather than a full
   flip-rate diagnostic requiring new full-sequence runs.

## GT-object transition analysis module

Implemented `repos/K-Radar/scripts/alvis/gt_transition_analysis.py` — a
read-only per-GT-object churn/retention diagnostic (stable /
corruption_induced_miss / corruption_induced_recovery / baseline_failure),
operating on the existing `all_predictions.parquet` sweep output. Reuses the
repo's own BEV-box convention (traced through `kitti_common.py`'s dims
reindex and `eval_revised.py`'s `bev_axes` selection) and its existing
numba-free rotated-IoU implementation (`rotate_iou_cpu.py`) rather than
reinventing box geometry. Supports arbitrary stratification (class, distance
bin, effect/severity parsed from condition names; occlusion/weather left as
an external-join extension point since they're not in the current parquet
schema). Unit-verified against synthetic frame data — the sanity assertion
(`N_stable+N_miss+N_recover+N_fail == total`) and all four transition
categories checked correct. Not yet run against the real sweep output.

Full detail in [[gt-transition-analysis]].
