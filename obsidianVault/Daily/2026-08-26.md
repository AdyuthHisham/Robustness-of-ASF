## Explained ASF/K-Radar mAP calculation end-to-end (inference → text dump → AP)

Walked the full mAP mechanism on request, from live inference output through to the final
scalar, reading actual code (not the paper) in `repos/K-Radar`: `pipelines/pipeline_detection_v1_0.py`,
`models/head/rdr_spcube_head_multi_cls.py`, `utils/util_pipeline.py`, `utils/kitti_eval/{kitti_common,eval_revised}.py`.
Written up as [[asf-map-eval-mechanics]], linked from [[asf-training-inputs]] and
[[robustness-metric-selection]].

Notable findings not previously documented in the vault:

- The KITTI 2D-bbox field written for both GT and predictions is a **hardcoded dummy**
  (`50 50 150 150`), which makes the KITTI difficulty-tier (easy/normal/hard) height/occlusion/
  truncation filter a structural no-op in this pipeline — worth knowing before treating
  per-difficulty AP splits as meaningful.
- Confirmed AP is a **41-point recall-spaced pooled** metric (KITTI devkit reimplementation,
  not COCO/VOC-style), TP/FP/FN summed across the whole dataset before precision is computed —
  the exact mechanism behind the frame_deletion survivorship-bias bug documented in
  [[asf-corruption-study-alvis]].

## Built context-breakdown radar charts; surfaced and fixed a frame-identifier bug in the K-Radar eval pipeline

Built [[context-radar-charts]] (54 charts: mAP/mASE/mATE × time_of_day/weather/environment ×
class × severity), extending [[robustness-radar-charts]]. `bus`/`university` mAP reading exactly
0% across every condition including clean baseline was implausible enough to investigate —
traced to [[frame-identifier-bug]]: `pipeline_detection_v1_0.py` named dumped GT/pred files by
loop position (`idx_datum`), not real frame number, corrupting frame identity throughout
`row_table_iou03.parquet` (proven against real Alvis data: `idx_datum=117` for seq 8 → real
frame 450, exactly where seq 8's buses begin). AP/ATE/ASE values themselves are unaffected
(pred/GT pairing per `idx_datum` stays internally consistent) — only frame identity was wrong.

Fixed in `repos/K-Radar` (4 files) with a canonical `{rdr}-{ldr64}` frame id, plus a related bug
in the same code paths: `except` blocks referenced a possibly-undefined-or-stale `dict_out`,
which could have silently reintroduced frame misattribution on any inference failure. Full
report: `docs/vAIlt/06_Results/frame-identifier-bug-fix-report.md`. Verified statically and via
logic/simulation tests (no local GPU/spconv); waiting on the user's Alvis re-sweep with the fix
before regenerating charts/tables from corrected data.

## Official-checkpoint ASF re-run: infra fixes, a data-loss bug, and a validated baseline mAP

Re-ran ASF on Alvis with the official published checkpoint (`ASF_v2_0_final_10.pt`) instead of
the self-trained one the original sweep used (see [[asf-corruption-study-alvis]]). Built
`scripts/alvis/run_batched_sweep.sh` to script the batch-submit/merge/delete-raw cycle that was
previously manual. Found and fixed two real bugs while standing it up: Alvis's login-node
`python3` is 3.6.8 (too old for `merge_predictions_text.py`), and — more seriously — an
`sbatch --export=ALL,...,SEQS=1,2,...,10` value got silently truncated at the first comma by
`sbatch`'s own comma-delimited syntax, so a batch-scoped merge only ever processed sequence 1
while the driver deleted all 10 sequences' raw dumps believing it had covered all of them.
**Sequences 2–7's raw dumps from that run were permanently lost** (caught before 8–10 were hit).
Fixed with a `+`-delimited `--seqs`, an outright refusal on comma-containing values, and a hard
gate verifying the merge log's processed-sequence count before any deletion. Full incident
writeup: [[official-checkpoint-rerun-2026-08-26]].

Plan changed mid-session: deleted all of this session's corruption-sweep-attempt data and ran
just the 58-sequence `original` (clean) baseline instead — all 58 completed cleanly. Computed
pooled mAP for sedan/bus at IoU 0.7/0.5/0.3 two independent ways (`ingest.py`+`ap_metrics.py`,
and K-Radar's own official `eval_revised.py` run by the user) — BEV AP agreed to within ~0.01
between the two, a strong correctness signal. Also surfaced that 3D AP (the more rigorous metric)
is meaningfully lower than BEV at higher IoU, and that the official eval's bbox/AOS columns
aren't meaningful (dummy 2D bbox, per [[asf-map-eval-mechanics]]). Full table in
[[official-checkpoint-rerun-2026-08-26]].

Also discovered — during this verification, not before — that the frame-identifier fix from
earlier today was never actually deployed: `asf_run.sbatch`'s bind-mount list doesn't include
`pipelines/pipeline_detection_v1_0.py`, so every job ran the container's stale baked-in copy.
Updated [[frame-identifier-bug]] with this correction; the bug's original AP-correctness nuance
held (re-verified via today's cross-validation), but the fix still needs the bind-mount added
before it actually takes effect.

The 33-condition corruption sweep with the official checkpoint has not been completed yet —
deferred in favor of validating the baseline first. `run_batched_sweep.sh` is fixed and ready to
resume it.
