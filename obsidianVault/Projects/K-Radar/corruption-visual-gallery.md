# Corruption Visual Gallery

Frame-level qualitative sanity check: does each of the 22 sweep conditions actually look like what
its name claims, on a real frame? Not a metrics artifact — companion to the quantitative results
in [[robustness-metrics-tables]] / `outputs/alvis_smoke/RESULTS.md`.

**Script:** `repos/K-Radar/datasets/effects/generate_corruption_gallery.py` (parameterized —
`--seq/--rdr-idx/--ldr-idx/--cam-idx/--label`)
**Output:** `repos/K-Radar/figures/corruption_gallery/*.png` (24 images) +
`repos/K-Radar/docs/corruption_visual_gallery.md`
**Frame used:** seq 1, rdr_idx=160, ldr_idx=128, cam_idx=383 (`seq001_rdr160`) — 7 GT objects, the
local max found by sampling `info_label_rev2` object counts every ~40 frames then narrowing around
the best hit (frames 157–163 all plateau at 7 objects; 160 picked as the plateau midpoint). Night
highway scene, multiple vehicles. Originally generated against seq 46/frame 205 (3 objects); user
asked for a busier seq-1 frame instead — same script, re-run with `--seq 1 --rdr-idx 160
--ldr-idx 128 --cam-idx 383 --label seq001_rdr160`. All three raw sensor files confirmed present
on the sshfs-mounted Alvis data dir.

## Design decisions

- **Reused, not reimplemented**: raw-file loaders (`load_rdr_sparse`/`load_lidar_pcd`/`load_camera_img`)
  and BEV/camera renderers (`render_bev`, `render_bev_zeroout`, `tensor_to_bgr`) from
  `datasets/effects/visualize_effects_v2.py` — that script already established the standalone
  pattern (no K-Radar `Dataset` object, no ASF model, no dataloader) for exactly this kind of
  single-frame corruption inspection.
- **Radar rendering = scatter-point BEV** (power-colored), not a `radar_zyx_cube` heatmap slice —
  matches every other viz script in this codebase and what the corruption functions/ASF model
  actually operate on (`rdr_sparse`). User confirmed this choice explicitly.
- **Severity params pulled from `configs/noise/single/*.yml`** (the canonical single-effect sweep
  configs, generated by `scripts/alvis/gen_single_effect_configs.py`) rather than re-derived —
  guarantees the gallery matches the actual mAP-sweep parameters: radar/lidar gaussian_noise sigma
  0.1/1.0/2.0, camera gaussian_noise sigma 20/50/80, all three loss_partial fraction 0.1/0.3/0.7,
  loss_complete_zero unconditional (no severity axis).
- **`frame_deletion` excluded** — drops whole frames rather than altering per-frame content, not
  meaningful in a static single-frame comparison.
- **22 conditions → 24 unique images**, not 22×3=66: each condition name already bakes in its
  modality (`camera_gaussian_noise_high` only touches the camera), so rendering "clean" companion
  images for the two untouched modalities per condition would mostly duplicate `original` 21 times
  over for no diagnostic value. Kept to one image per condition + one `original` per modality
  (3+21=24).

## Findings

No conditions flagged as no-op (per-pixel/per-row perceptual-diff check, thresholds in the script).
`loss_complete_zero` renders as a single dot near the origin for radar/LiDAR — expected: the
non-zero-aware `render_bev` collapses all-identical zero-filled points to one pixel (same known
rendering quirk documented in [[../../Knowledge/asf-training-inputs]]'s taxonomy discussion /
`docs/vAIlt/04_Design/Noise_Taxonomy.md`), not a bug.
