## Document: k-radar-sensor-visibility-metrics.md
- **Purpose:** **Scope:** For every annotated 3D object per frame, define a boolean `*_visible` and continuous `*_score` per sensor, under CPU-only, lazy-loading, vectorized constraints. K-Radar bboxes are `(x,y,z,θ,l,w,h)` with **half-extents**; convert to full extents (`2l, 2w, 2h`) before any volumetric computation — this is the single most common bug source and is flagged explicitly in every formula below.
- **Key Concepts:** Scope:, half-extents, Object frame: box center `c=(x,y,z)`, yaw `θ` about z, full dimensions `L=2l, W=2w, H=2h`., Point-in-box test (any sensor): rotate point into box frame, `R(-θ)(p-c)`, then check `|Δx|≤L/2, |Δy|≤W/2, |Δz|≤H/2`. This is O(N) per object, O(N·M) per frame for N points, M objects — vectorize via broadcasting (N×M) rather than looping, and pre-filter with an axis-aligned bounding box (AABB) or KD-tree/range query to keep it CPU-tractable (KITTI devkit and OpenPCDet's `points_in_boxes_cpu` use exactly this two-stage filter, Geiger et al. 2012; OpenPCDet, Team OpenPCDet 2020)., Degrade gracefully: if a sensor file is missing/unreadable, set `visible=False, score=0.0` and log — never raise.
- **Architecture:** **Occlusion handling:** partial — a fully radar-shadowed object (rare, e.g., large flat metal truck directly in front) shows depressed excess power; not explicitly modeled, could add a ray-based shadow check (see §4). **Complexity:** O(k) per object for the box sum + O(cube size) once per frame for the noise-floor map (can be precomputed frame-globally, amortized). Memory: reuses the already-loaded collapsed cube, no extra tensor. **Pros:** normalizes for per-frame/weather noise floor (critical in K-Radar's rain/fog/snow splits); differentiable-friendly; already selected and validated in your pipeline. **Cons:** sensitive to guard-cell/training-cell window size; azimuth/elevation resolution is coarse (107°/37° FOV over limited bins) so small or distant objects (motorcycle, pedestrian) may span very few cells → noisy score; multipath ghosts near large metal vehicles (buses/trucks) inflate excess power outside the true object footprint. **K-Radar suitability:** best available compromise given CPU-only + no full 4DRT; recommended as core radar score.
- **Key Patterns:** visible = (count{cells in bbox : P(cell) > τ}) > 0, N_local(cell) = median or mean power in a guard-banded ring around cell (per-frame CFAR noise floor), For a moving ego + moving/static object, expected Doppler v_exp is computable from, 1. **Expected-density normalization (2.2)** — implicit occlusion sensitivity, free., 2. **Ray-casting/frustum occupancy (2.3)** — explicit, distinguishes occluder-caused misses from self-occlusion/range-limit misses, moderate cost via range-image rasterization.
